## Scenarios and checks

- `testStatusIndicatorStatesDuringHealthCheck`: the last confirmed healthy indicator stays green while a background health check is pending.
- `testRecoveryRetainsDiagnosticUntilFailedHealthReturns`: the confirmed red error remains during recovery checking and changes to green only after health returns.
- `testSharingPresentationSurvivesPendingRenewalUntilRecovery`: sharing state stays visible while peer operations are unavailable; consent, incoming proposal and pairing controls are captured in English and Spanish.
- `testRecoveredHelperRestartClearsInvalidatedInvitationAtSameEndpoint`: a valid QR remains visible while recovery is pending and an invalidated QR is removed after a same-endpoint helper restart.
- `testSharingPollPreservesConfirmedStateDuringRetryAndClearsAfterTerminalFailure`: the same source-review draft stays open, Apply is disabled while health is unavailable, and returns after recovery; terminal failure preserves the draft while keeping Apply disabled.
- `testPairedDevicesRemainVisibleDuringRetryWhenSharingIsOff`: the paired-device row remains visible during health retry.
- `testStatusSectionHeightDoesNotChangeWithDiagnosticOrApproval`: one-line and wrapped diagnostics and the approval action do not change section height.

All seven focused checks passed on the captured source using `swift test --disable-automatic-resolution --skip-build --filter …`; no compiler invocation was needed. A separate full suite and packaged-app guide smoke test are recorded in PR #428. The captures below are component evidence only.
